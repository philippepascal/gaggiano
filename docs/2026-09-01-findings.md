# Gaggiano: state of the project and tooling (findings, 2026-09-01)

Snapshot taken before the migration away from the Arduino IDE. Everything below was
verified on this Mac (Darwin 25.6, Apple Silicon) on 2026-09-01. Paths are absolute so
the document stays useful from any working directory.

The dead sketchbook path is the most likely single cause of the IDE feeling flaky: the IDE
cannot find `libraries/`, recent-sketch entries are broken, and the board/port memory is
per-workspace so it resets.

## 2. The two firmware targets

### 2.1 STM32 controller (`gaggiano-controller-v1/`)

- Hardware: STM32F411CEU6 "Black Pill". Reads MAX6675 thermocouple (bit-banged SPI on
  PA5/PA6/PB4), ADS1115 pressure sensor over I2C (PB6/PB7), drives boiler SSR on PB5 via
  hardware timer PWM (30 Hz), pump via PSM zero-cross dimming (PA15 sense, PB3 control),
  solenoid on PC13. Talks to the screen on USART2 (PA2 TX / PA3 RX) at 115200.
- Debug output on USB CDC `Serial` at 9600.
- Files: `gaggiano-controller-v1.ino`, `PSM.cpp/.h` (copied from banoz/PSM.Library).
- Libraries used: AutoPID, SimpleKalmanFilter, ADS1X15, MAX6675, Wire.
- Arduino core: **STMicroelectronics:stm32 2.9.0** (installed; the index now lists 2.11.0, we stay pinned).
- Exact FQBN (from the archived `build.options.json`, matches the screenshot in the folder):

  ```
  STMicroelectronics:stm32:GenF4:pnum=GENERIC_F411CEUX,xserial=generic,usb=CDCgen,xusb=FS,opt=osstd,dbg=none,rtlib=nanofp,upload_method=dfuMethod
  ```
  Extra build property used by the IDE: `build.warn_data_percentage=75`.
- Archived build (2025-03-28): `.bin` 67,140 bytes, `.hex` 188,906 bytes. Source has
  changed since (last edit 2025-09-28) so expect a nearby but not identical size.

### 2.2 ESP32-S3 display (`gaggiano-v2/`)

- Hardware: Sunton ESP32-8048S043, 4.3" 800x480 RGB panel (ST7262), GT911 capacitive touch
  on I2C (SDA 19 / SCL 20 / RST 38), SD card on SPI (SCK 12 / MISO 13 / MOSI 11 / CS 10),
  USB-to-serial via CH340 (VID 0x1a86 PID 0x7523). 16 MB flash, 8 MB OPI PSRAM.
- Talks to the controller on UART2, RX GPIO 18 / TX GPIO 17, 115200. Debug on `Serial` 115200.
- SD card layout used by the firmware: `/gaggia/gaggia_settings.csv`, `/gaggia/profiles/`,
  `/gaggia/selectedProfile`, `/gaggia/gaggia_logs.csv`, `/gaggia/frank.bmp` (+ generated
  `frank_opt.bin`). The card is FAT.
- Files: `gaggiano-v2.ino`, `lv_buildUI.c/.h` (LVGL UI), `gaggia_config.cpp/.h` (SD,
  profiles, logs), `gaggia_state.h`, `gaggia_utils.*`, `touch.h`, `BmpClass*.h`,
  `my_logging.*`, plus LVGL image arrays (`*.c`).
- Libraries used: lvgl 8.3.3 with project `libraries/lv_conf.h` (16-bit color, no swap,
  custom tick, perf monitor on), Arduino_GFX ("GFX Library for Arduino") 1.2.8, TAMC_GT911,
  SD, FS, SPI, Wire, CSV_Parser. `touch.h` includes FT6X36/XPT2046 headers only inside
  `#ifdef` blocks that are off, so those libraries are not needed.
- Arduino core: **esp32:esp32 2.0.17** (installed). Latest is 3.3.2. Upgrading is a real
  port (Arduino_GFX API changed, lvgl 8 to 9), out of scope for this migration.
- Exact FQBN (archived `build.options.json`, matches the screenshot `esp32-arduino.png`):

  ```
  esp32:esp32:esp32s3:UploadSpeed=460800,USBMode=hwcdc,CDCOnBoot=default,MSCOnBoot=default,DFUOnBoot=default,UploadMode=default,CPUFreq=240,FlashMode=qio,FlashSize=16M,PartitionScheme=default,DebugLevel=none,PSRAM=opi,LoopCore=1,EventsCore=1,EraseFlash=none,JTAGAdapter=default
  ```
  Every option value above exists in the installed `boards.txt` (`UploadSpeed=460800` is
  defined for macOS and Linux only).
- Partition scheme is "default" (4 MB layout: app0/app1 1.25 MB each, 1.4 MB SPIFFS) even
  though the chip has 16 MB. A `partitions.csv` identical to the default is in
  `archiveArdIDEFiles/`. App size limit is 1,310,720 bytes; the archived build was
  1,048,672 bytes (80%). Something to watch as the UI grows.
- Archived build (2025-03-28): `.bin` 1,048,672, `.bootloader.bin` 15,104,
  `.partitions.bin` 3,072.

### 2.3 Screen-to-controller protocol (for reference)

ASCII lines, fields separated by `;`, terminated by `|` then newline. First field is the
message type: `0` status from controller (temp, pressure, solenoid, boiler out, pump out,
setpoint, PID params, loop counter), `1` brew (temp;pressure), `2` steam
(temp;maxPressure;pumpPercent), `3` clean (temp;pressure), `9` advanced settings (10 floats).

How the IDE actually uploads today:

- STM32: `stm32CubeProg.sh -i dfu -f <sketch>.bin -o 0x0 -v 0x0483 -p 0xdf11`, which runs
  `STM32_Programmer_CLI --connect port=usb1 VID=0x0483 PID=0xdf11 --quietMode --download <bin> 0x8000000 --start 0x8000000`.
- ESP32: `esptool --chip esp32s3 --port <cu.usbserial-XXXX> --baud 460800 --before default_reset --after hard_reset write_flash -z --flash_mode qio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 sketch.bin`.

## 4. USB identities (why the STM32 is "not detected")

| Device state | VID:PID | Shows up as | Notes |
|---|---|---|---|
| STM32 running our firmware | 0483:5740 | `/dev/cu.usbmodem<serial>` (CDC) | this is the port seen in the IDE screenshot |
| STM32 in DFU (system bootloader) | 0483:df11 | **no `/dev/cu.*` entry** | raw USB device; only visible via `dfu-util -l`, `STM32_Programmer_CLI -l usb`, or `system_profiler SPUSBDataType` |
| STM32 in DFU, seen by IDE | | "STM32 BOOTLOADER" via dfu-discovery | the IDE's DFU discovery is what usually fails to refresh |
| ESP32 board (CH340) | 1a86:7523 | `/dev/cu.usbserial-XXXX` or `/dev/cu.wchusbserial*` | esptool auto-resets; no buttons |
| ESP32-S3 native USB | 303a:1001 | `/dev/cu.usbmodem*` | not used: `CDCOnBoot=default` (off) and `USBMode=hwcdc` |

All five VID:PIDs above (plus one unknown 1963:0072) appear in the IDE's board-lookup cache
(`~/Library/Arduino15/inventory.yaml`), confirming these are the devices that were plugged in.

Entering DFU on the Black Pill: hold BOOT0, press and release NRST, release BOOT0. The
bootloader is in ROM and cannot be bricked by firmware. Two quirks recorded in the sketch's
own comments: (a) the solenoid relay interferes with DFU enumeration, and turning brew on
first helps; (b) USB CDC must be enabled in the build for `Serial` to exist at all.

## 6. Decisions taken on 2026-09-01

- Target repo is `~/repos/Gaggiano`, work happens on branch `migration`.
- Build system: `arduino-cli` driven by a repo script, not PlatformIO.
- Cores stay pinned at STM32 2.9.0 and esp32 2.0.17. No library upgrades.
- ST-Link/SWD stays an optional path (no soldering for now); DFU remains the default.
- A small firmware change to enter DFU from a serial command is approved, provided the
  BOOT0/NRST button sequence keeps working as the fallback (it does: the bootloader is in ROM).
- Repository cleanup is in scope, as a separate phase after the build is proven.

See `docs/MIGRATION-PLAN.md` for the step-by-step plan.
